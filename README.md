# 🏛️ 博物馆世界 · Museum Explorer

全球知名博物馆（中国 + 国外约 30 家）的**文物照片与说明**浏览站：按国家/地区筛选、当下热门博物馆、
**每日更换**的今日推荐文物与热门检索词、站内检索、**全球展览资讯**（中英混合，每日滚动）、以及
**文物打卡**（点图 / 点详情 / 点维基百科均计入"已看"数量）。

## ✨ 核心功能

| 模块 | 说明 |
| --- | --- |
| 国家/地区筛选（第一行） | 中国 / 美国 / 英国 / 法国 / 荷兰 / 意大利 / 西班牙 / 日本… |
| 当下热门博物馆 | 按游客量（参考 The Art Newspaper）+ 网页访问 + 社媒提及综合热度排序，热门带 🔥 角标 |
| 今日推荐文物 | 每天零点自动更换一批（16 件），由**日期种子确定性生成** |
| 今日热门检索词 | 每天更换 5 个，点击即检索 |
| 站内检索 | 按标题 / 说明 / 维基摘要 / 馆名全站匹配 |
| 全球展览资讯 | Google News（中英）+ ARTnews 等 RSS 聚合，每日刷新，来源跳原文 |
| 文物打卡 | 本浏览器 localStorage 记录，点图片 / 详情 / 维基百科均计一次，顶栏显示"已看 N 件" |
| 维基百科关联 | 有词条的文物自动关联维基百科（中文优先），无词条则不显示链接 |
| 官网来源 | 每件文物附官方来源链接（开放 API 馆直达官网藏品页） |

## 🔧 技术结构

```
museum-explorer/
├─ public/data/           生成的静态数据（站点唯一数据来源）
│  ├─ museums.json        博物馆元数据 + 热度 + 精选文物数
│  ├─ artifacts.json      全部精选文物（图/说明/百科/官网链接）
│  ├─ news.json           全球展览资讯（每日刷新）
│  └─ today.json          今日批次（日期种子抽取的推荐与热门词）
├─ scripts/               数据管道（Node ESM）
│  ├─ museums.mjs         约30家博物馆元数据
│  ├─ curated.mjs         精选文物清单（~190件，覆盖各馆知名文物）
│  ├─ fetch-wikidata.mjs  Wikidata 解析：标题/说明/共享资源图/维基百科链接
│  ├─ fetch-official.mjs  官方开放 API 增强：MET / 芝加哥艺术学院 / 克利夫兰
│  ├─ fetch-palace.mjs    故宫数字文物库探测（可用则接入官网图）
│  ├─ fetch-news.mjs      资讯 RSS 聚合（中英源）
│  ├─ build-data.mjs      编排 + 每日批次生成
│  └─ lib.mjs             工具（日期种子/缓存/HTTP）
├─ src/                   React 前端（Vite）
└─ .github/workflows/     daily-data.yml 每日自动刷新数据
```

### 数据来源（官方优先 + 维基兜底）

- **官方开放 API（图+说明来自官网）**：大都会 MET、芝加哥艺术学院、克利夫兰艺术博物馆、（故宫数字文物库可用时接入）
- **维基共享资源兜底（附官网链接）**：卢浮宫、大英博物馆、台北故宫、MoMA、史密森尼等
- 图片版权归各博物馆/权利人所有；本页仅作学习浏览用途，点击文物可跳转官网原页

### 每日更换如何做到"不死链"

今日推荐 / 热门检索词由 `日期字符串 → 哈希种子 → 确定性洗牌` 生成：

1. **服务端每天凌晨由 GitHub Actions 生成** `today.json`（与客户端算法完全一致）；
2. **客户端内置相同算法**——即使定时任务某天没跑，页面也会用当天日期算出**同一批**推荐；
3. 图片三级兜底（大图 → 缩略图 → 占位图），不会出现红叉；
4. 纯静态站，无运行时后端依赖，不会因服务端故障变死链。

## 🚀 本地运行

```bash
pnpm install
pnpm run data      # 首次拉取数据（需要网络；后续命中本地缓存会很快）
pnpm run dev       # 开发预览 http://localhost:5173
pnpm run build     # 构建静态站到 dist/
pnpm run preview   # 预览 dist/
```

## ☁️ 部署与每日刷新

**前端**（纯静态，任意静态托管均可）：
- **Cloudflare Pages**：连接仓库即可，构建命令 `pnpm run build`，输出目录 `dist`
- **Vercel**：同样连接仓库，框架选 Vite
- **GitHub Pages**：Actions 里加一个静态部署 job，或使用 `actions/deploy-pages`

**每日数据刷新**：把仓库推到 GitHub，`.github/workflows/daily-data.yml`
会自动每天 05:17（北京时间）跑一遍数据管道并提交新的 `public/data/*.json`，
托管平台检测到推送后自动重新部署 → 资讯与热度保持每日更新。

> 即使不部署到公网，本地 `pnpm run dev` 也完全可用：今日推荐靠日期种子本地生成，
> 资讯模块显示最后一次抓取的快照（页面永远可打开）。

## 🎫 打卡说明

- 点击文物卡片图片、打开详情、点击维基百科链接均计入"已看"数量；
- 记录仅保存在**当前浏览器**（localStorage），换设备不继承；
- 已看过的文物卡片左上角显示"✓ 已看"。

## 📝 说明

- 说明文字保留原文语言（中文馆显中文、国外馆显英文），不做机器翻译；
- 维基百科摘要用于补充背景（有词条才展示）；
- 数据管道对每个外部接口都有重试与缓存，单个接口失败不影响整站生成。
